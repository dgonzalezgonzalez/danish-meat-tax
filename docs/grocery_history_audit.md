# Grocery change-history audit

The frozen dagligepriser.dk JSON contains `priceHistory` entries for changes in a product's price, quantity, or unit. It is not a daily posted-price panel. The snapshot has no complete historical product–store availability record. A missing event month can mean an unchanged posted price, an unavailable product, or failed collection. No forward fill can distinguish these cases from this source alone. The grocery regression therefore describes **recorded event prices conditional on repricing**; its product–store clustered standard error is not national-policy uncertainty. The grocery pre-period mean used as a DKK/kg level anchor is also provisional and not expenditure weighted.

`data/reference/grocery_beef_jev_audit.csv` records TypeSafe Jev labels and probabilities for the 392 distinct product names that the original rule classifier flagged as beef. The categories are core beef, prepared beef, mixed food, plant product, animal feed, and other. Jev labeled 163 names core beef, 104 animal feed, 73 prepared beef, 39 mixed food, 10 other, and 3 plant product. The frozen estimation screen requires `core_beef` probability at least 0.90, then excludes two identified false positives (`Cup Noodles` and `Oksebryst i skiver`), leaving 118 names. An assistant text-only pass read the retained names against their displayed descriptions for obvious species and product-type errors. This is not independent human adjudication and cannot verify package contents, historical package size, or retailer availability. Jev labels are a screening aid, not ground truth or a measured classifier precision. The CSV contains no credential. `scripts/audit_beef_jev.py` can reproduce the external audit with an ephemeral `--key-stdin` key; ordinary offline preprocessing reads the saved CSV and makes no API call.

The Stata audit `scripts/stata/grocery_history_audit.do` reads the processed Stata panel and counts observed months between each unit's first and last record, excluding June 2024 and keeping units with events on both sides of the policy date. The output is `outputs/models/stata/grocery_event_support.csv`. In the screened beef sample, 151 product–store pairs have events in 1,105 of 2,552 within-span months (43.3%). For 13,754 control pairs the share is 53.3%. These fractions measure event recording, not shelf availability. The audit reads the `.dta` rather than the CSV to preserve quoted product fields and source values.

Eligibility is now computed after restricting records to October 2023–September 2025. A product with a qualifying event only after the paper's endpoint cannot borrow that event to enter the estimation sample. `outputs/diagnostics/panel_eligibility_reconciliation.csv` records full-history and within-window pre/post event counts for every screened product–store unit, inclusion, and exclusion reason. A frozen copy of this 45,637-unit ledger is committed as `data/reference/panel_eligibility_reconciliation.csv` (SHA-256 `9aa51607beb45c38c99efaf69622c518489b3d53ce28cded9ce9f4fcce2728c2`). It identifies 1,675 units with support outside the window, including 406 beef units. The Stata estimation sample and support audit now agree exactly: 151 beef units and 1,105 beef event-months. The earlier 156/1,112 sample counted five beef units whose eligibility depended on later events. The ledger contains unit identifiers and support counts, not product names or price histories.

Package normalization first uses explicit source quantity and unit fields. If they are absent, a name such as `2 x 400 g` is parsed as 800 g. This fallback is still a text heuristic and cannot validate a mislabeled package. Processed rows retain `history_change_event` and `snapshot_unavailable` flags, so the source limitation remains visible in downstream records. A price-spell analysis would require archived daily snapshots or dated availability, with a separate assessment of survivorship and retailer coverage.
